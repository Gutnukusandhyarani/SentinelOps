# Deploy SentinelOps hosted mode on Render

**Important: this Blueprint requires a paid web service and a persistent disk. Review the cost with a parent/guardian before creating or approving it.** Render currently lists the smallest paid web-service compute at about US$7/month and persistent disks at US$0.25/GB/month; the included 1 GB disk therefore adds about US$0.25/month. Prices can change and taxes/other usage may apply. Do not proceed unless the cost is understood and approved.

1. Commit the updated project package contents to the root of `Gutnukusandhyarani/SentinelOps` on `main`. The changed/new files are `sentinelops/server.py`, `sentinelops/ingest.py`, `sentinelops/store.py`, `web/index.html`, `web/app.js`, `web/styles.css`, `scripts/push_events.py`, `tests/test_remote_ingest.py`, `tests/test_public_api.py`, `README.md`, `docs/hosted-deployment.md`, `requirements-hosted.txt`, and `render.yaml`.
2. In Render, create a new Blueprint and connect the SentinelOps repository. Review every resource in `render.yaml` before continuing.
3. Confirm the service has a paid compute plan and a 1 GB persistent disk mounted at `/var/data`. SQLite is configured at `/var/data/sentinelops.db`; using the free filesystem would lose records during restarts/deploys.
4. Confirm `SENTINELOPS_PUBLIC_MODE=1`, `SENTINELOPS_INGEST_TOKEN` is generated by Render, and `SENTINELOPS_RULES_PATH=rules/imported_sigma.json`. Never enter the token into GitHub or the frontend.
5. Deploy and verify the service root URL loads the aggregate-only SentinelOps dashboard. Check `/api/health` returns `status: ok` and `public_mode: true`.
6. Open the Render Environment page. Reveal/copy the generated `SENTINELOPS_INGEST_TOKEN` only into the authorized collector machine's local environment. Do not paste it into ChatGPT, a GitHub commit, website JavaScript, screenshots or messages.
7. On an authorized Linux lab endpoint, set the secret in the local shell environment and run the included collector with your actual service URL:

   ```bash
   export SENTINELOPS_INGEST_TOKEN='the-secret-from-your-private-service-settings'
   python scripts/push_events.py --file /var/log/auth.log --type ssh --url https://YOUR-SERVICE.onrender.com
   ```

   The collector starts at the current end of the file and sends newly appended lines. Use `--from-start` only when intentionally uploading an existing lab log. Do not send workplace/customer logs or private personal logs to this portfolio service.
8. Generate a few known test events on a dedicated lab system or use a sanitized test log. The public dashboard should update aggregate event/alert totals on its 15-second refresh. The dashboard does not display usernames, IPs, hostnames, process names or raw messages.

## Limits to understand

- This portfolio version uses one shared bearer token, not per-device identity or multi-tenant authentication.
- SQLite on a Render disk requires a single service instance. Do not scale this service horizontally.
- Raw event evidence is still stored privately in the service database even though the public dashboard omits it. Only send events you are authorized to collect and retain.
- The current Windows PowerShell collector is a read-only batch export. It is not a continuously running Windows agent.
- This is a learning/portfolio project, not a production SIEM or a security monitoring service for other people or businesses.
